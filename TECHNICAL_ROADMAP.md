# TECHNICAL_ROADMAP.md

## Проект

**Life Maps** — персональный локальный навигатор жизненных событий, здоровья и семьи. Текущая версия — клиентский React-прототип; production-ready статус не подтверждён.

## Текущее состояние

- Ветка разработки: `chore/initial-technical-roadmap`.
- Базовая ветка: `main` (только чтение; изменения запрещены).
- UI: React 18, TypeScript, Vite, Tailwind CSS 4; без Figma UI runtime и неиспользуемых UI-китов.
- Библиотеки: motion, Recharts, lucide-react.
- Интерфейс feature-разделов реализован на JSX и Tailwind CSS; неиспользуемый каталог shadcn/Radix UI-заготовок удалён.
- Точка входа: `src/main.tsx` → `src/app/App.tsx`.
- `App.tsx` декомпозирован: корневой компонент отвечает за layout и маршрутизацию разделов; feature-компоненты находятся в отдельных файлах.
- Верхнеуровневые разделы: Карта жизни, Здоровье, Семья, Аналитика.
- Здоровье содержит вкладки анализов, вакцинации и стоматологии; предусмотрен отдельный экран здоровья ребёнка.
- Данные заданы статическими константами. Изменения форм и статусов хранятся в React state и не переживают перезагрузку.
- Backend, API, база данных, авторизация и надёжное постоянное хранилище отсутствуют.
- Скрипты package.json: `dev` и `build`. Автотесты, lint и отдельная проверка TypeScript пока не настроены.
- `OVERVIEW.md` синхронизирован с фактическими разделами и текущей структурой модулей.
- Медицинские тексты и статусы — демонстрационные данные, не проверенная персональная медицинская рекомендация.

## Архитектурные правила

1. Разделять UI, доменную логику, типы, данные и инфраструктуру.
2. Переиспользуемые компоненты размещать отдельно от компонентов конкретных разделов.
3. Один файл — не более 1500 строк; целевой размер — до 300–500 строк, если это улучшает читаемость.
4. Не дублировать типы, форматирование, валидацию и общие UI-паттерны.
5. Не добавлять зависимости без обоснования; предпочитать бесплатные решения без обязательных внешних API.
6. Не добавлять backend/облако/аналитику/телеметрию без отдельного решения по приватности и безопасности.
7. Не хранить реальные медицинские и семейные данные в исходном коде, тестовых фикстурах или публичных репозиториях.
8. Любые медицинские справочники и подсказки должны иметь проверяемые источники, страну/версию рекомендаций и дату актуализации. Не ставить диагнозы и не назначать лечение.
9. Не заявлять о production-ready до проверки сборки, ключевых пользовательских сценариев, хранения данных, обработки ошибок и приватности.
10. Обновлять этот файл при изменении архитектуры, статуса этапа, ограничений или планов.

## Запрещено

- Изменять, переписывать или коммитить что-либо в `main`.
- Удалять пользовательские данные или менять механизм их хранения без анализа миграции и резервного копирования.
- Подключать платные API/сервисы или делать их обязательными.
- Создавать монолитные файлы более 1500 строк.
- Оставлять временные заглушки, фиктивные показатели или неподтверждённые медицинские утверждения как реальные данные.
- Выполнять destructive-команды, сбрасывать БД или перезаписывать данные без явного согласования.
- При конфликте сохранять обе версии или возвращать старую: выбирать только более новую версию файла.
