# Life Maps

Локальное приложение для ведения карты жизненных событий, семейной информации и личной медицинской истории.

## Требования

- Node.js 22 или совместимая LTS-версия.
- npm.

## Запуск

```bash
npm ci
npm run dev
```

## Проверка типов

```bash
npm run typecheck
```

## Тесты

```bash
npm test
npm run test:e2e
```

Unit-тесты выполняются Vitest. E2E smoke-тесты запускаются Playwright в Chromium; команда автоматически поднимает локальный Vite dev server.

## Production-сборка

```bash
npm run typecheck
npm test
npm run build
```

Сборка создаётся Vite в каталоге `dist/`.

## Технологии и UI

React 18, TypeScript, Vite, Tailwind CSS 4, Motion, Recharts, Lucide, Vitest и Playwright. Интерфейс реализован непосредственно в feature-компонентах на JSX и Tailwind CSS. Неиспользуемый каталог шаблонных shadcn/Radix-компонентов удалён; приложение не зависит от Figma UI-блоков или Figma runtime.

## Текущее состояние

Интерфейс приложения работает в браузере, а пользовательские записи по-прежнему сохраняются локально в IndexedDB. Дополнительно реализован self-hosted API для регистрации, входа и ручного переноса зашифрованной резервной копии между устройствами. Для серверного режима требуется развернуть собственный API; он не включается автоматически.

Реализованы карта жизни, медицинская история, контроль показателей и проверок, семейные профили взрослых и детей, вакцинация, стоматологические записи, аналитика и единый календарь. Детские медицинские данные разделены по профилям. Экспорт и импорт резервной копии поддерживают вложенные документы и защиту от перезаписи устаревшей вкладкой.

Актуальный статус этапов, критерии завершения и журнал работ находятся в [TECHNICAL_ROADMAP.md](./TECHNICAL_ROADMAP.md). Не используйте справочники и демонстрационные примеры как персональные медицинские рекомендации.

## Локальные данные и резервные копии

Без входа в аккаунт пользовательские изменения хранятся только в IndexedDB текущего браузерного профиля. После настройки собственного сервера и входа в аккаунт можно вручную отправить полную резервную копию на сервер или восстановить её на другом устройстве. Платные облачные сервисы не используются.

Сохраняются карта жизни, семейные записи, профили детей, статусы вакцинации, стоматологические записи и загруженные файлы результатов анализов. В панели «Экспорт / Импорт» можно скачать JSON-резервную копию или восстановить данные из неё. Импорт заменяет текущий локальный набор данных и требует подтверждения.

Резервную копию рекомендуется хранить отдельно от устройства. Очистка данных сайта, удаление профиля браузера или поломка устройства могут привести к потере локальной базы. Файл резервной копии содержит персональные и медицинские сведения, поэтому храните его в защищённом месте и не отправляйте в публичные репозитории или чаты.

Формат резервной копии имеет версию схемы. Вложения включаются в JSON в base64-представлении. Максимальный размер файла резервной копии — 100 МБ; максимальный размер одного загружаемого результата — 15 МБ.

## Установка на мобильное устройство

Life Maps подготовлен как устанавливаемое веб-приложение (PWA). После публикации приложения по HTTPS:

- **Android (Chrome):** откройте адрес приложения → меню браузера → «Установить приложение» или «Добавить на главный экран».
- **iPhone/iPad (Safari):** откройте адрес приложения → «Поделиться» → «На экран Домой».
- **Компьютер (поддерживаемый браузер):** используйте значок установки в адресной строке или меню браузера.

Название, цвет темы и значки задаются в `public/manifest.webmanifest`, `public/icon.svg` и `public/apple-touch-icon.png`. Production service worker сохраняет оболочку приложения и статические ресурсы для повторного открытия без сети; первый запуск и первая загрузка ресурсов требуют подключения. Медицинские записи остаются в IndexedDB этого устройства, а запросы API и синхронизация между устройствами требуют интернета. Перед очисткой данных браузера создавайте резервную копию. Подробная инструкция по установке и офлайн-режиму — [docs/pwa-mobile-accessibility.md](./docs/pwa-mobile-accessibility.md).


## Аккаунт и синхронизация между устройствами

Добавлен self-hosted API для регистрации и входа по email и паролю, серверных сессий и хранения резервной копии пользователя. Серверная копия шифруется AES-256-GCM и разделена по аккаунтам. Автоматическая синхронизация передаёт изменения и вложения, сохраняет offline-очередь и обнаруживает конфликты ревизий; независимые изменения объединяются, конфликтующие поля требуют явного выбора.

Для запуска собственного сервера см. [инструкцию по развёртыванию](./docs/self-hosting.md) и [эксплуатационный runbook](./docs/operations-runbook.md). Понадобятся собственный VPS/сервер, домен и Docker; платные облачные сервисы не используются. Docker Compose запускает API, Caddy с автоматическим HTTPS и отдельный ежедневный backup worker. Публичный сервер автоматически не развёрнут.

Подтверждение email, сброс пароля и автоматическая фоновая синхронизация пока не реализованы. До настройки SMTP аккаунт создаётся без письма подтверждения. При переносе данных на устройство импорт заменяет его локальную базу, поэтому интерфейс требует явного подтверждения.
